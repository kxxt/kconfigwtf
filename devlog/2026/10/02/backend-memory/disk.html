Proposed lifecycle

StartRead one JSON index at a time. Write integer occurrence pairs to one private temporary file.
→
ServeKeep offsets, value tables, and kernel metadata in RAM. Read only the requested config's occurrences.
→
Stop / restartClosing the file removes it. A restart rebuilds from the data tree, so no persistent cache invalidation is needed.

Concrete implementation choices

  1. Storage format and lookup: one private binary file of 8-byte pairs (32-bit kernel ID + 32-bit value ID). An in-memory config-name map holds package IDs, offsets, and lengths. Per-package tables retain shared values and precomputed kernel metadata. Use existing Rust standard-library, Serde, and tempfile dependencies; no database or schema migration.
  2. Storage location: add optional serve --cache-dir PATH and KCONFIGWTF_CACHE_DIR. Without either, use the operating system's temporary directory, preserving an easy CLI startup. Document explicitly choosing a disk-backed directory: /tmp is tmpfs on this host. Update the NixOS service to use CacheDirectory=kconfigwtf and pass /var/cache/kconfigwtf; systemd makes that directory writable for the service. Keep data/ read-only.
  3. File lifetime and failures: rebuild a fresh file on every startup; no reuse across restarts, data hashing, or persistent-cache cleanup. Keep the file private and automatically remove it on close. Fail startup with context if the directory is unavailable, disk is full, or an index is invalid. Return HTTP 500 if a later file read fails.
  4. Concurrency: perform disk reads and result generation in Tokio blocking tasks, with at most 8 simultaneous config lookups; additional lookups wait. Hold each permit until its task completes, including cancelled requests. Use positional file reads on Unix, with a locked seek/read fallback on other platforms. Health, frontend, and raw-file routes retain their existing behavior.
  5. Compatibility: directly parse compact indexes one at a time; retain legacy support through the existing loader and per-file conversion. Preserve missing values, duplicate precedence, package shards, stored architecture spellings, ordering, response JSON, raw URLs, ETags, and cache headers. Indexers and on-disk JSON remain unchanged.
  6. Validation: add focused compatibility and file-failure tests; run the full test suite, formatting, and Clippy; compare full-dataset sampled HTTP responses; measure startup, idle, and request peaks at concurrency 8 and 64. Require measured RSS below 500 MiB. Document the final result, temporary disk requirement, and distinction between RSS and total cgroup memory.

These choices were approved and implemented. Legacy compatibility, bounded query concurrency, configurable storage, and the NixOS integration have been validated. Dataset growth and arbitrary numbers of connections remain outside a fixed memory guarantee.
